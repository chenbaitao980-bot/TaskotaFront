# brainstorm: 桌面悬浮进行中任务页签

## Goal

为 Windows 桌面版增加一个在主窗口关闭后仍可见的桌面悬浮页签，用于展示当前时间节点正在进行的任务，降低“应用被隐藏到托盘后完全失去桌面入口”的问题，同时允许用户在“我的-设置”里控制该页签默认启用或关闭。

## What I already know

* 当前桌面版已经接入 `window_manager` 和 `system_tray`，主窗口点击关闭按钮后会被隐藏到托盘，而不是退出进程。
* 当前托盘菜单已经支持“显示”和“退出”，并且窗口可被重新显示和聚焦。
* “我的-设置”页面已经通过 `LocalStorageService` 持久化多个本地偏好项，适合继续承载桌面悬浮页签的默认开关。
* 该项目已经存在桌面本地模式 `LocalAuthenticated`，且用户偏好会写入 `SharedPreferences`，并纳入本地数据快照。
* 这次需求发生在桌面端壳层 + 前端表现层，不应影响云登录主路径和移动端行为。

## Assumptions (temporary)

* 首个版本仅面向 Windows 桌面版。
* 悬浮页签只在主窗口被关闭/隐藏后显示，主窗口恢复显示后自动消失。
* 页签默认出现在桌面右上角，并允许拖动改变位置。
* 用户说的“右键点击任务栏可以选择关闭”暂按“右键点击悬浮页签可出现关闭菜单”理解；若要改成系统任务栏右键菜单，需要进一步确认。
* 悬浮页签同一时刻只展示 1 个“当前最该做”的进行中任务；若存在多个候选，可为后续版本预留数量提示。
* 点击悬浮页签后，应用恢复主窗口并直接打开该任务详情页。
* 当存在多个 `in_progress` 任务时，沿用首页现有“优先级 + 时间紧迫度”综合得分逻辑选出展示对象。

## Open Questions

* 当前无阻塞性开放问题，等待最终需求确认后进入实现。

## Requirements (evolving)

* Windows 桌面版主窗口关闭后，不再仅保留托盘入口，还要保留一个桌面悬浮页签。
* 悬浮页签同一时刻只展示 1 个“当前最该做”的进行中任务。
* 如果同时存在多个 `in_progress` 任务，需要按首页现有“优先级 + 时间紧迫度”综合得分规则选出唯一展示任务。
* 如果当前没有任何进行中任务，则不显示悬浮页签。
* 悬浮页签默认停靠在桌面右上角。
* 悬浮页签允许用户拖动调整位置。
* 点击悬浮页签后，应用需要恢复主窗口并直接导航到该任务详情页。
* 悬浮页签支持右键关闭。
* “我的-设置”里需要提供一个默认开启/关闭该桌面悬浮页签的设置项。
* 设置项应使用当前本地偏好存储机制持久化。

## Acceptance Criteria (evolving)

* [ ] 在 Windows 桌面版中，主窗口关闭后会出现桌面悬浮页签，而不是只剩托盘。
* [ ] 悬浮页签同一时刻只展示 1 个进行中任务，不展开为多任务列表。
* [ ] 存在多个进行中任务时，展示对象与首页现有“优先级 + 时间紧迫度”排序逻辑保持一致。
* [ ] 当前没有进行中任务时，不显示悬浮页签。
* [ ] 悬浮页签首次出现时位于桌面右上角。
* [ ] 用户可以拖动悬浮页签到其他位置。
* [ ] 点击悬浮页签后会恢复主窗口，并直接打开该任务详情页。
* [ ] 用户可通过右键操作关闭该页签。
* [ ] “我的-设置”中可以配置该页签默认启用或关闭，重启应用后仍生效。
* [ ] 移动端和 Web 端行为不受影响。

## Out of Scope (explicit)

* 不在本任务中设计完整桌面小组件系统。
* 不在本任务中改变现有托盘菜单的整体信息架构，除非实现悬浮页签必须调整。
* 不在本任务中扩展到 macOS / Linux / mobile / web。
* 不在首版中把悬浮页签扩展为多任务列表、快捷操作面板或完整桌面看板。
* 不在首版中增加“无任务空态页签”或常驻桌面入口。

## Technical Notes

* 现有桌面关闭隐藏逻辑位于 `lib/platform/window_manager_bridge_desktop.dart`。
* 现有托盘初始化与菜单逻辑位于 `lib/platform/tray_service_desktop.dart`。
* 现有设置入口位于 `lib/presentation/pages/profile/app_settings_page.dart`。
* 现有本地偏好持久化入口位于 `lib/services/local_storage_service.dart`。
* 应优先复用现有桌面窗口/托盘/本地偏好模式，避免新建与主应用状态脱节的独立持久化机制。
* 任务详情导航入口已存在，可通过全局路由或现有任务详情页导航模式恢复主窗口后直达任务。
* 首页四象限逻辑已经包含“优先级 + 时间紧迫度”综合排序思路，适合作为悬浮页签选题规则的单一来源，避免重复发明另一套评分标准。

## Technical Approach

* 复用现有桌面窗口生命周期：主窗口关闭时不退出进程，改为在隐藏主窗口后根据配置与当前任务状态决定是否显示桌面悬浮页签。
* 新增桌面悬浮页签承载层，负责桌面右上角初始定位、拖动位置更新、右键关闭和点击恢复主窗口。
* 在桌面任务选择逻辑中复用现有任务数据与评分规则，选出唯一展示任务；若无匹配任务则不渲染悬浮页签。
* 在“我的-设置”中新增桌面页签默认开关，并写入 `LocalStorageService`，保持与现有本地偏好快照一致。

## Decision (ADR-lite)

**Context**: 主窗口关闭后现状只剩托盘入口，桌面端缺少一个低打扰但可立即回到“当前该做什么”的可见入口；同时用户明确希望这是一个轻量页签，而不是完整桌面面板。

**Decision**: 首版实现一个仅面向 Windows 的桌面悬浮页签。它只在主窗口隐藏后出现，只展示 1 个“当前最该做”的进行中任务；多任务时沿用首页现有“优先级 + 时间紧迫度”综合得分逻辑选出唯一任务；无进行中任务时不显示。点击页签恢复主窗口并直达任务详情页，右键可关闭；是否默认启用由“我的-设置”控制。

**Consequences**: 首版实现路径清晰，能最大化复用现有桌面壳、设置持久化和任务导航能力，风险较低。代价是它暂不覆盖多任务汇总、常驻空态入口和更复杂的桌面交互，这些需要在后续版本中单独扩展。
